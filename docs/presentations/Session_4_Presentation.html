Types of Databases

SQL (Relational) Databases

Organized data into tables with rows and columns. Think of it like a collection of spreadsheets where tables can be linked together.

  • Schema: Predefined structure (strong schema).
  • Examples: SQLite, MySQL, PostgreSQL.
  • Use Cases: Good for structured data like user profiles, inventory, game stats.

NoSQL Databases

A broad category of databases that don't use the traditional table-based relational model. They offer more flexibility.

  • Document Databases: Store data in JSON-like documents (e.g., MongoDB). Good for flexible, semi-structured data.
  • Key-Value Stores: Simple databases where data is stored as a key-value pair (e.g., Redis). Very fast for caching.
  • Graph Databases: Focus on relationships between data points (e.g., Neo4j). Excellent for social networks or complex relationships.

Step 1: Define Data Models

A data model is a C# class that mirrors the structure of a database table. Each property in the class corresponds to a column in the table.

User Preference Model

This model stores settings for a user, like theme and volume.

public class UserPreference
{
    [PrimaryKey, AutoIncrement]
    public int Id { get; set; }
    public string ThemeSetting { get; set; }
    public float SoundVolume { get; set; }
}
  • [PrimaryKey, AutoIncrement]: Marks 'Id' as the unique identifier for each row. The database will automatically assign a new number for each entry.

Game Score Model

This model stores individual game scores.

public class GameScore
{
    [PrimaryKey, AutoIncrement]
    public int Id { get; set; }
    public string PlayerName { get; set; }
    public int Score { get; set; }
    public string Level { get; set; }
    public System.DateTime DateAchieved { get; set; }
}

Each instance of this class will represent a single score entry in our database.

Step 2: Database Connection

Now we create a manager class to handle the database file and create tables based on our models.

Database Manager Skeleton

using SQLite;
using UnityEngine;
public class DatabaseManager : MonoBehaviour
{
    private SQLiteConnection _connection;
    void Awake()
    {
        // Path to the database file
        string dbPath = System.IO.Path.Combine(Application.persistentDataPath, "my_game_data.db");
        _connection = new SQLiteConnection(dbPath);
        
        // Create tables if they don't exist
        _connection.CreateTable<UserPreference>();
        _connection.CreateTable<GameScore>();

        Debug.Log("Database connected and tables created.");
    }
    void OnDestroy()
    {
        // Always close the connection when the object is destroyed
        if (_connection != null)
        {
            _connection.Close();
        }
    }
}
  • Application.persistentDataPath: A safe, writable directory on any device (PC, mobile, etc.). This is the correct place to store user data.
  • _connection.CreateTable<T>(): This is the magic command. It checks if a table for the given model (e.g., UserPreference) exists. If not, it creates it. If it already exists, it does nothing.

Step 3: CRUD - Create (Insert)

To add a new record to the database, we use the Insert method.

Adding a New Game Score

public void AddGameScore(string playerName, int score, string level)
{
    var newScore = new GameScore
    {
        PlayerName = playerName,
        Score = score,
        Level = level,
        DateAchieved = System.DateTime.Now
    };
    
    _connection.Insert(newScore);
    // After insertion, newScore.Id will be populated with the new ID.
    Debug.Log($"Game score added for {playerName} with ID: {newScore.Id}");
}
  • First, create an instance of your data model (GameScore).
  • Then, simply pass this object to the _connection.Insert() method.
  • SQLite-net handles the conversion from a C# object to a database row.

Step 3: CRUD - Read (Query)

To get data from the database, you can query the table. This is like asking the database for records that match certain criteria.

Get a Single Record

Use FirstOrDefault() to get the first matching item or null if none is found. Good for unique items like player settings.

public UserPreference LoadPlayerSettings()
{
    // Returns the first entry in the UserPreference table.
    return _connection.Table().FirstOrDefault();
}

Get Multiple Records

Use LINQ methods like Where(), OrderByDescending(), and Take() to build powerful queries.

public List GetTopScores(int count)
{
    return _connection.Table()
                      .OrderByDescending(s => s.Score)
                      .Take(count)
                      .ToList();
}

This chain of commands gets all scores, sorts them from highest to lowest, takes the top count, and returns them as a List.

Step 3: CRUD - Update

To modify an existing record, you use the Update method. SQLite-net uses the Primary Key (Id) to find the right row to change.

Updating a User's Theme

public void UpdateTheme(UserPreference settings, string newTheme)
{
    settings.ThemeSetting = newTheme;
    _connection.Update(settings);
    Debug.Log($"Theme updated to {newTheme} for ID: {settings.Id}");
}
// --- How you would use it ---
// 1. First, load the settings
var currentSettings = LoadPlayerSettings();
if(currentSettings != null)
{
    // 2. Then, call update
    UpdateTheme(currentSettings, "Dark");
}
  • You must first have an object that has been retrieved from the database.
  • Modify the properties of that object.
  • Pass the modified object to _connection.Update(). The Id tells SQLite which record to update.

Step 3: CRUD - Delete

To remove a record, use the Delete method, passing the primary key of the item you want to remove.

Deleting a Score

public void DeleteScore(int scoreId)
{
    // The generic parameter  tells the DB which table to look in.
    _connection.Delete(scoreId);
    Debug.Log($"Score with ID {scoreId} has been deleted.");
}
// --- How you would use it ---
// 1. Get the ID of a score you want to delete
int idToDelete = someScore.Id;
// 2. Call the delete method
DeleteScore(idToDelete);
  • The Delete method is very efficient. It only needs the table and the Id of the row you want to remove.
  • It's a permanent action, so be careful!
