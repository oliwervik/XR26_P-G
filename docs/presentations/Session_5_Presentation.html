Why Networking is Complex

Latency

Data takes time to travel between devices. Even on fast internet, expect 20-100ms delays. Players notice delays over 150ms.

Packet Loss

Sometimes data doesn't arrive. Networks can lose 1-5% of packets. Games must handle missing information gracefully.

State Synchronization

Keeping all players seeing the same game state is challenging when updates arrive at different times.

Bandwidth Limits

Can't send everything to everyone. Must prioritize important data and compress information efficiently.

Network Architectures

Client-Server

How it works: One central server manages the game state. All players connect to this server.

  • Pros: Secure, prevents cheating, scalable
  • Cons: Requires dedicated server, single point of failure
  • Best for: Competitive games, persistent worlds

Peer-to-Peer

How it works: Players connect directly to each other. No central server needed.

  • Pros: Lower latency, no server costs, distributed
  • Cons: Harder to prevent cheating, NAT traversal issues
  • Best for: Cooperative games, small groups

Network Protocols: TCP vs UDP

TCP (Transmission Control Protocol)

Reliable and Ordered: Guarantees all data arrives in the correct order.

  • Automatically resends lost packets
  • Maintains connection state
  • Higher overhead and latency
  • Good for: Chat messages, file transfers, web browsing
  • Real-world example: Downloading a file - you need every byte

UDP (User Datagram Protocol)

Fast and Connectionless: Sends data quickly without guarantees.

  • No automatic retransmission
  • Lower overhead and latency
  • Can lose or duplicate packets
  • Good for: Real-time game data, voice chat, live video
  • Real-world example: Live sports broadcast - missing a frame is better than delay

Unity Netcode Choice

Unity Netcode uses UDP as the base protocol but adds reliability layers on top when needed. This gives you the speed of UDP with the reliability of TCP when required.

Unity Netcode Core Concepts

NetworkManager

The central coordinator for all networking. Handles connections, spawning, and overall network state.

NetworkObject

Makes any GameObject network-aware. Required for objects that exist across multiple clients.

NetworkBehaviour

Base class for scripts that need networking features. Like MonoBehaviour but with network capabilities.

Spawning

Creating objects that appear on all connected clients. Essential for shared game elements.

9

Network Roles

Host

Acts as both server and client. Manages the game state while also playing. Good for small groups and testing.

  • Easiest to set up
  • No dedicated server needed
  • Host has advantage (no latency)

Server

Dedicated game state manager. Doesn't play, just manages the game for all clients. Most authoritative setup.

  • Fair for all players
  • Best for competitive games
  • Requires separate machine

Client

Connects to server or host. Sends input and receives game state updates. Most players will be clients.

  • Receives game state
  • Sends player input
  • Displays game world

Network Ownership & Authority

Server Authority

Server makes the final decisions on game state.

  • Position validation: Server checks if movement is valid
  • Game rule enforcement: Server prevents cheating
  • State synchronization: Server sends authoritative updates
// Server validates player movement if (IsServer && IsValidMovement(newPosition)) { transform.position = newPosition; // Send to all clients }

Client Authority

Clients control specific objects they own.

  • Player movement: Client moves immediately, server validates
  • Input handling: Client processes input locally
  • Visual feedback: Immediate response for better feel
// Client sends movement to server if (IsOwner) { // Move locally for immediate feedback transform.position = newPosition; // Send to server for validation RequestMoveServerRpc(newPosition); }

Simple Networked Player Example

Basic NetworkedPlayer Script

using Unity.Netcode;
using UnityEngine;
using Unity.Netcode;

public class Player : NetworkBehaviour
{
    public float moveSpeed = 5f;

    private void Update()
    {
        // Only process input for the local player
        if (!IsOwner) return;

        Vector3 input = new Vector3(
            Input.GetAxis("Horizontal"),
            0f,
            Input.GetAxis("Vertical")
        );


        Vector3 move = input * moveSpeed * Time.deltaTime;

        // Send the movement to the server
        MoveServerRpc(move);
    }

    [ServerRpc]
    private void MoveServerRpc(Vector3 move, ServerRpcParams rpcParams = default)
    {
        // Apply movement on the server
        transform.position += move;
    }
}

NetworkVariable Examples

Player Health Example

public class Player : NetworkBehaviour
{
    // Automatically syncs across all clients
    private NetworkVariable<int> health =
        new NetworkVariable<int>(100);
    
    public override void OnNetworkSpawn()
    {
        // Listen for health changes
        health.OnValueChanged += OnHealthChanged;
    }
    
    private void OnHealthChanged(int oldValue, int newValue)
    {
        Debug.Log($"Health changed from {oldValue} to {newValue}");
        UpdateHealthBar(newValue);
    }
    
    [Rpc(SendTo.Server)]
    public void TakeDamageServerRpc(int damage)
    {
        if (IsServer)
        {
            health.Value = Mathf.Max(0, health.Value - damage);
        }
    }
}

Game Score Example

public class GameManager : NetworkBehaviour
{
    private NetworkVariable<int> score =
        new NetworkVariable<int>(0);
    
    private NetworkVariable<float> gameTime =
        new NetworkVariable<float>(0f);
    
    void Update()
    {
        if (IsServer)
        {
            gameTime.Value += Time.deltaTime;
        }
    }
    
    [Rpc(SendTo.Server)]
    public void AddPointsServerRpc(int points)
    {
        if (IsServer)
        {
            score.Value += points;
            Debug.Log($"Score is now: {score.Value}");
        }
    }
}

RPC (Remote Procedure Call) Examples

Chat System

public class ChatManager : NetworkBehaviour
{
    [Rpc(SendTo.Server)]
    public void SendMessageServerRpc(string message,
                                   ulong senderId)
    {
        // Server receives and broadcasts to all
        ReceiveMessageClientRpc(message, senderId);
    }
    
    [Rpc(SendTo.AllClients)]
    public void ReceiveMessageClientRpc(string message,
                                      ulong senderId)
    {
        // All clients display the message
        string playerName = GetPlayerName(senderId);
        DisplayMessage($"{playerName}: {message}");
    }
    
    public void SendChatMessage(string message)
    {
        SendMessageServerRpc(message, NetworkManager.LocalClientId);
    }
}

Sound Effects

public class SoundManager : NetworkBehaviour
{
    [Rpc(SendTo.AllClients)]
    public void PlaySoundClientRpc(int soundId, Vector3 position)
    {
        // Play sound on all clients at specific position
        AudioSource.PlayClipAtPoint(
            GetSoundClip(soundId),
            position
        );
    }
    
    public void PlayNetworkedSound(int soundId)
    {
        // Only server can trigger sounds for all
        if (IsServer)
        {
            PlaySoundClientRpc(soundId, transform.position);
        }
    }
    
    [Rpc(SendTo.Server)]
    public void RequestSoundServerRpc(int soundId, Vector3 pos)
    {
        // Client requests server to play sound
        PlaySoundClientRpc(soundId, pos);
    }
}

Connection Management Code

Simple Connection UI

using Unity.Netcode;
using UnityEngine;
using UnityEngine.UI;

public class NetworkUI : MonoBehaviour
{
    [SerializeField] private Button hostButton;
    [SerializeField] private Button clientButton;
    [SerializeField] private Button disconnectButton;
    [SerializeField] private Text statusText;
    
    void Start()
    {
        hostButton.onClick.AddListener(StartHost);
        clientButton.onClick.AddListener(StartClient);
        disconnectButton.onClick.AddListener(Disconnect);
        
        // Subscribe to connection events
        NetworkManager.Singleton.OnClientConnectedCallback += OnClientConnected;
        NetworkManager.Singleton.OnClientDisconnectCallback += OnClientDisconnected;
    }
    
    void StartHost()
    {
        NetworkManager.Singleton.StartHost();
        statusText.text = "Starting as Host...";
    }
    
    void StartClient()
    {
        NetworkManager.Singleton.StartClient();
        statusText.text = "Connecting as Client...";
    }
    
    void Disconnect()
    {
        NetworkManager.Singleton.Shutdown();
        statusText.text = "Disconnected";
    }
    
    void OnClientConnected(ulong clientId)
    {
        statusText.text = $"Client {clientId} connected";
    }
    
    void OnClientDisconnected(ulong clientId)
    {
        statusText.text = $"Client {clientId} disconnected";
    }
}

Real-World Networking Examples

Online Games

Fortnite: Uses client-server with 100 players. Server validates all actions to prevent cheating.

Minecraft: Can use peer-to-peer for small groups or dedicated servers for larger communities.

Video Streaming

YouTube Live: Uses UDP for speed. If some video frames are lost, the stream continues rather than pausing to resend.

Chat Applications

Discord: Uses TCP for text messages (must arrive) and UDP for voice chat (speed over reliability).

File Sharing

Google Drive: Uses TCP to ensure every byte of your document arrives correctly. Missing data would corrupt the file.
